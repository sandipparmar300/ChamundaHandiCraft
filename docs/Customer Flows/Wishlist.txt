Module 9 - Wishlist
1. Module Overview
Module Name

Wishlist

Purpose

The Wishlist module allows customers to save products for future purchase, organize favorite items, move products to the shopping cart, remove products, and receive notifications about stock availability and price changes.

Business Goals
Increase customer retention.
Encourage repeat visits.
Reduce purchase hesitation.
Increase future conversions.
Support personalized marketing.
Increase Average Order Value (AOV).
Track customer interests.
Improve shopping experience.

18. Business Rules
Only authenticated customers can maintain a permanent wishlist.
Guest wishlists may be stored in the browser session or cookies (configurable).
Wishlist items should not reserve inventory.
Products removed from the catalog should be hidden or marked as unavailable.
Price and stock information should always reflect current product data.
Products requiring variant selection must prompt the customer before moving to the cart.
Wishlist count should update in real time across all pages.
Duplicate wishlist entries for the same product/variant are not allowed.

27. Recommended .NET 8 Architecture

Implement the Wishlist as an independent Wishlist Module within the Customer Domain of your .NET 8 Modular Monolithic Architecture. Use CQRS with command handlers for add, remove, and move-to-cart operations, and optimized query handlers for retrieving customer wishlists. Store wishlist data in SQL Server using Entity Framework Core, while leveraging Dapper for fast read operations. Cache wishlist counts using Redis or IMemoryCache to provide instant UI updates. Publish domain events when products are added or removed to support analytics, personalized recommendations, marketing campaigns, and future notification features (such as price drop and back-in-stock alerts). This approach provides a scalable, maintainable, and enterprise-ready wishlist solution.
