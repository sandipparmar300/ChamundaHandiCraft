Module Name

My Account

Purpose

The My Account module provides customers with a centralized dashboard to manage their personal information, addresses, orders, wishlist, reviews, account security, notifications, and other account-related activities.

Improve customer self-service.
Increase customer retention.
Enhance customer engagement.
Reduce customer support requests.
Improve account security.
Provide complete order visibility.
Increase repeat purchases.
Centralize customer account management.

20. Business Rules
Only authenticated customers can access My Account.
Customers can only access their own profile and data.
Email and mobile numbers must remain unique.
Address validation should verify serviceable delivery locations.
Orders can only be cancelled or returned according to configured policies.
Reviews can only be submitted for eligible purchased products (configurable).
Password changes require current password verification.
Sensitive actions (password changes, profile updates) should be recorded in audit logs.
Notifications should respect customer communication preferences.
Dashboard statistics should reflect real-time account activity.

Recommended .NET 8 Architecture

Implement My Account as a dedicated Customer Module within your .NET 8 Modular Monolithic Architecture. Separate each feature (Profile, Addresses, Orders, Wishlist, Reviews, Notifications, Security) into independent application services. Use CQRS for read-heavy operations like dashboard summaries and order history, Dapper for optimized customer queries, and Entity Framework Core for transactional updates. Cache dashboard statistics and frequently accessed profile data using Redis or IMemoryCache. Ensure strict authorization so every request is scoped to the authenticated customer, providing a secure, scalable, and enterprise-grade account management experience.
